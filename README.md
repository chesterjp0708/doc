現在、まず自分のPCで基本的な検証を行っています。
第1段階の基本機能は、ほぼ動く状態になっています。今は、計算、条件判断、繰り返し、文字列処理など、比較的独立したC++の処理をPythonに変換できます。
変換した後は、元のC++と変換後のPythonをそれぞれ実行して、同じ結果になるかを確認します。
簡単に言うと、C++の文字をそのままPythonに置き換えるのではありません。まずコードが何をしているかを確認し、その内容をPythonで作り直して、最後に実行結果を比較する方法です。
AIは、通常の方法では変換できない部分を補助するために使います。例えば、少し複雑な関数をAIに変換させます。ただし、AIが作ったコードをそのまま使うことはありません。元のC++と結果を比較し、問題がない場合だけ採用します。
現在、会社のAIアカウントはまだ発行されていません。そのため、今は全体の流れを中心に確認しており、AI部分はシミュレーションによるテストまでです。会社環境で実際のAIサービスに接続する検証は、アカウント発行後に行う予定です。
また、現在の成果は自分のPC上で作成したものです。会社のPCでは、開発環境やコンパイラの設定、ツールの再構築と確認が必要です。必要なソフトウェアと権限が準備できれば、会社環境で第1段階を再構築するまでに、約1～2週間を想定しています。
今後は、三つの段階で進める予定です。
第1段階は、現在自分のPCで動いているものを会社環境で再構築し、会社のコードでも問題なく使えるかを確認することです。
第2段階では、対象を「一つの関数」から「小さなモジュール」へ広げます。この部分はまだ着手しておらず、改めて設計と実装が必要です。複数ファイルの関係、関数同士の呼び出し、外部ライブラリなどに対応します。Pythonへの変換が難しい部分は、無理に変換せず、C++のまま残してPythonと一緒に動かす方法も考えます。
第3段階では、プロジェクト全体を対象にします。ただし、すべてのC++コードを一度にPythonへ変換するという意味ではありません。まずプロジェクト全体を確認し、自動変換できる部分、AIや人の対応が必要な部分、C++のまま残した方がよい部分に分けて、少しずつ移行します。
そのため、「C++プロジェクト全体をワンクリックで、すぐに使えるPythonプロジェクトへ変換する」という状態までは、まだかなり距離があります。これは短期間で約束できる目標ではありません。
現時点では、「第1段階は自分のPCでほぼ動いている。次に1～2週間程度で会社環境へ再構築する。その後、実際の小さなモジュールで第2段階を試し、プロジェクト全体の移行に必要な期間と作業量を判断する」という説明が一番実情に近いです。
